# Blockers

- `vp.loss.kl`, `vp.loss.mse`, `vp.loss.declared_psd`, and `vp.loss.declared_psd_matrix_free` are implemented with explicit assumptions because SPEC requires them but only partially defines their constructor details. Current assumptions: KL reads a target-probability tensor with the same shape as logits and uses target-row mass to scale the softmax Hessian; MSE uses squared-error semantics with Hessian `2I` under the declared reduction; declared-PSD treats `factors` as a dense output-space matrix `L` defining `H = L @ L.T`; declared-PSD matrix-free treats `matvec(output, vector)` as an output-space Hessian product, uses the full output dimension as the certificate iteration budget, uses zero PSD tolerance, and densifies the output-space Hessian after certification because the existing GGN runtime consumes `loss_hessian`.
- Public exact categorical Fisher is intentionally rejected to GGNVP. Public Gaussian `vp.likelihood.gaussian(...)` and executable public `vp.fisher_vp(...)` now exist with score-gradient reference coverage. Public `SampleSource`, `vp.samples.fixed_seed(...)`, `vp.samples.table(...)`, and `vp.sampled_fisher_vp(...)` now lower fixed-table and fixed-seed sampled score-gradient rows for Gaussian and categorical likelihoods.
- Public exact-Fisher comparison for sampled Fisher still has a SPEC/API gap: `vp.samples.fixed_seed(seed, count)` and `vp.samples.table(table=..., identity=...)` expose no bound-formula argument, while SPEC says the sample source carries the sampling-bound formula id when exact-Fisher comparison is enabled. The public default keeps exact comparison disabled; the lower runtime exact-comparison path still exists.
- Public `vp.metric.kfac(...)` now exists, and `vp.damping.kfac_pi(...)` carries kind/policy identity and executes the factored shift. Non-`None` KFAC metric-owned `dampings` still rejects because no spec-defined lowering exists separate from typed `vp.damping.*`.
- `vp.damping.per_group(...)` lowers for typed diagonal, block-diagonal, and KFAC metrics. It preserves the per-block map in operator identity and executes inverse, inverse-inner, and inverse-sqrt products with public behavior tests. Remaining scope gap: dense, low-rank, GGN-derived, EKFAC, and matrix-free metrics have no spec-defined string group map, so those pairings reject.
- Typed inverse `tol` lowers for `inverse_metric_vp` and `inverse_metric_inner_vp` matrix-free CG rows: it is carried in operator identity, stops CG, and sets the accepted inverse residual. `inverse_sqrt_metric_vp(..., tol=...)` is still rejected because SPEC lists the argument but gives no residual rule for inverse square-root factor application.
- Matrix-free metric representation and executor now exist: public matrix-free metric multiply, positive-damping CG inverse, matrix-free Lanczos square-root paths, metric inner product, and inverse-metric-inner solve residual checks bind to selected sibling products. Remaining matrix-free work is matrix-free preconditioner lowering and the wider acceptance-test sweep beyond the focused public/runtime tests already present.
- Low-rank and GGN-derived closed-form square-root paths now execute with the SPEC factor semantics and focused standard-runtime tests. Current shape assumption: direct forward `sqrt_metric_vp` over low-rank consumes a flat latent vector of width rank plus parameter count and returns a parameter tree; direct forward `sqrt_metric_vp` over GGN-derived consumes a flat output-space latent vector and returns a parameter tree; `sqrt_apply_reduce` uses the adjoint on parameter-shaped vectors. GGN-derived inverse square-root now uses the same low-rank-plus-diagonal inverse square-root rule as the Woodbury inverse solve and requires positive damping.
- Core `checkpoint_non_reentrant_by_layer` is rejected in the standard runtime until package-owned layer checkpoint lowering exists.
- `inverse_metric.preconditioner=matrix_free` is present but rejected until named sibling-product preconditioner lowering exists.
- Fusion coverage now verifies registered fused rows for HVP, GGNVP, FisherVP, sampled FisherVP, empirical FisherVP, and compositions. Remaining fusion gap: `fusion.loss=fused_ce` and `fusion.loss=fused_kl` require exact global normalization, but non-GGN loss/fisher rows do not expose a spec-defined normalization marker separate from the typed loss or likelihood.
- Public `vp.adapters.distributed.space(...)` now derives `distributed.launch`, `distributed.process_group_backend`, `distributed.local_rank_binding`, `distributed.mesh_shape`, and `distributed.mesh_dim_names` from `DistributedAdmissionPolicy` because the SPEC example supplies only `strategy=(...)` while distributed admission requires those fields. Current derivation: `rank_count > 1` selects `torchrun`, otherwise `single_process`; process-group backend comes from `policy.communication["backend"]`; local rank binding is `cuda_local_rank`; mesh shape and names come from `policy.device_mesh`.
