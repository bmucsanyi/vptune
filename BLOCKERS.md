# Blockers

- `vp.loss.kl`, `vp.loss.mse`, `vp.loss.declared_psd`, and `vp.loss.declared_psd_matrix_free` are implemented with explicit assumptions because SPEC requires them but only partially defines their constructor details. Current assumptions: KL reads a target-probability tensor with the same shape as logits and uses target-row mass to scale the softmax Hessian; MSE uses squared-error semantics with Hessian `2I` under the declared reduction; declared-PSD treats `factors` as a dense output-space matrix `L` defining `H = L @ L.T`; declared-PSD matrix-free treats `matvec(output, vector)` as an output-space Hessian product, uses the full output dimension as the certificate iteration budget, runs the Lanczos residual-bound certificate over a complete deterministic basis of starts, and densifies the output-space Hessian after the certificate because the existing GGN runtime consumes `loss_hessian`.
- Public exact-Fisher comparison for sampled Fisher still has a SPEC/API gap: `vp.samples.fixed_seed(seed, count)` and `vp.samples.table(table=..., identity=...)` expose no bound-formula argument, while SPEC says the sample source carries the sampling-bound formula id when exact-Fisher comparison is enabled. The lower runtime exact-comparison path currently admits an explicit abs/rel bound map for internal tests; SPEC instead names known matrix-Bernstein or Hutchinson relative-variance formula ids but does not define the constructor field or the formula inputs. The public default keeps exact comparison disabled; lower runtime and run-level admission reject exact-Fisher rows without a declared sampling bound.
- Public `vp.metric.kfac(...)` now exists, and `vp.damping.kfac_pi(...)` carries kind/policy identity and executes the factored shift. Non-`None` KFAC metric-owned `dampings` still rejects because no spec-defined lowering exists separate from typed `vp.damping.*`.
- Typed inverse `tol` lowers for `inverse_metric_vp` and `inverse_metric_inner_vp` matrix-free CG rows: it is carried in operator identity, stops CG, and sets the accepted inverse residual. `inverse_sqrt_metric_vp(..., tol=...)` is still rejected because SPEC lists the argument but gives no residual rule for inverse square-root factor application.
- `inverse_metric.preconditioner=matrix_free` is present but rejected until named sibling-product preconditioner lowering exists.
- Public `vp.adapters.distributed.space(...)` now derives `distributed.launch`, `distributed.process_group_backend`, `distributed.local_rank_binding`, `distributed.mesh_shape`, and `distributed.mesh_dim_names` from `DistributedAdmissionPolicy` because the SPEC example supplies only `strategy=(...)` while distributed admission requires those fields. Current derivation: `rank_count > 1` selects `torchrun`, otherwise `single_process`; process-group backend comes from `policy.communication["backend"]`; local rank binding is `cuda_local_rank`; mesh shape and names come from `policy.device_mesh`.
